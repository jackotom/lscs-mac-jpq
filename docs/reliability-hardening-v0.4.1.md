# v0.4.1 可靠性强化

## 目标

本轮不增加新功能，不推倒现有解析器。只强化套牌识别证据、日志会话隔离、OCR 稳定、缓存恢复、异常退出恢复和回放覆盖。

## 套牌识别证据

公开状态必须区分：

- `decks-log`：炉石日志明确记录，显示“炉石已确认”。
- `screen`：选牌页画面识别，显示“画面找到”。
- `inferred`：根据本方抽牌和出牌推断，显示“本局匹配”。

多个候选仍成立时不得直接装载最佳候选牌库。界面显示已观察卡数和候选数；只有候选唯一且至少观察到两张不同本方卡时，才允许装载推断牌库。保留 `autoMatchedDeckId` 一个版本，供旧界面和旧测试兼容。

## 会话隔离

每次开始监听都创建新的内部会话身份，即使日志路径相同也不能复用。日志读取、OCR、竞技场评分、精确竞技场牌库和其它延迟结果提交前必须核对当前会话。

会话身份不写入玩家名、卡组原文或完整日志内容。

## OCR 稳定

- 精确牌名允许单次确认。
- 模糊牌名必须连续两次得到相同结果。
- 左、中、右槽位独立保留稳定结果。
- 已有完整三张时，后续不完整结果不能降级当前显示。
- 日志恢复提供完整候选时，继续以日志为准。

## 竞技场衍生牌恢复

- `Arena.log` 中带小写衍生后缀的卡牌编号必须按完整编号解析，例如 `TIME_009t1`、`TIME_009t2`。
- 本地卡牌库已有资料时，右侧牌表必须显示中文名称、费用和卡牌详情，不能退化为内部编号和问号。
- 衍生牌没有独立统计时，选取率和影响继续显示 `—`，不能伪造为 `0`。

## 缓存恢复

卡牌和竞技场评分缓存统一执行：

1. 写临时文件。
2. 重新读取并验证。
3. 将当前有效文件保存为单份备份。
4. 原子替换正式文件。
5. 正式文件损坏时尝试上一份有效备份。

卡牌缓存增加 schema 版本；旧格式继续读取，成功刷新后写成新格式。派生缓存版本不兼容时重建，不维护复杂迁移链。

## 异常退出恢复

本地运行标记只保存版本、启动时间、阶段和结束时间。正常退出标记为 clean；下次启动发现 running 时写入本地诊断日志。运行标记不得保存玩家、套牌、日志正文、Token 或其它账号内容。

## 验收

- 相似套牌不能因微弱领先被静默选中。
- 旧 OCR、旧评分请求和旧日志读取不能污染新监听会话。
- 同一日志整段、逐行和固定种子随机分块回放结果一致。
- 重复开局和重复事件不产生重复状态。
- 一万行代表性输入可完成回放，结果正确，不使用机器速度硬阈值。
- 缓存半写入、损坏、旧格式和断网均能保留最后有效数据或给出明确错误。
- 类型检查、全量测试、正式构建和发布验证全部通过。
- 使用真实 `OnChoicesAndContents` 格式回放带小写后缀的衍生牌，牌名和费用能够恢复。
- 打包版主窗口与悬浮窗显示不同套牌证据状态，窄窗不截断关键含义。
