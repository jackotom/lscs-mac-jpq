# 项目结构

这是一个 Electron + React + TypeScript 的 Mac 桌面工具。

- `src/main/`：桌面窗口、日志发现、文件监听、和系统对话框。
- `src/shared/`：卡组解析、炉石日志解析、记牌状态模型。
- `src/renderer/`：应用界面。
- `tests/`：解析和状态模型测试。

## 边界

只读取本机日志文件；竞技场选牌和标准/狂野/休闲选牌页需要确认当前套牌时，会在获得 macOS 屏幕录制许可后临时识别炉石画面文字。默认只读取炉石窗口；全屏炉石没有窗口源时，仅在已确认炉石处于前台后读取鼠标所在显示器，不会读取其它显示器。临时图片识别后立即删除，不会上传或长期保存。不会读取游戏内存、注入炉石进程或做自动操作。

正式安装包只加载随应用打包的本地页面，不接受环境变量指定的外部页面。开发模式只允许无账号信息的本机 HTTP 地址，主窗口和所有辅助窗口共用同一加载边界。

### 对局结束与牌表生命周期

- 对局结束只清空手牌、场上、墓地、移除区、对手记录、事件和本局计数；已确认的构筑套牌、手动导入套牌或竞技场正式牌库恢复到完整初始数量并保留到下一局。
- 启动恢复不能只凭整个 `Player.log` 曾出现过开局记录和文件更新时间，把已结束对局重新标成进行中。若 `LoadingScreen.log` 已明确处于大厅、选牌或其它非 `GAMEPLAY` 页面，该页面状态优先否决旧开局记录；双方场攻、奥秘和智能计数窗口随 `gameActive=false` 立即关闭。
- 本局生成、洗入和临时未识别的牌不会带入下一局；自动推断出的套牌只在局间用于显示，下一局开始时释放并重新识别，避免换套牌后被旧结果锁住。
- 新日志会话、模式切换和离开竞技场使用明确的清牌边界；用户手动导入的套牌在炉石日志目录自动切换时保留。
- 竞技场 `CREATE_GAME` 与构筑开局使用同一对局生命周期，结束后牌表不归零，构筑切竞技场且没有竞技场牌库时不会显示旧构筑牌。

- 自动扫描常见 Mac 炉石日志路径。
- 手动选择日志文件或日志目录。
- 打开软件时先执行启动检修：验证软件数据目录可完成创建、写入、读取、改名和清理，检查主界面、安全桥接、竞技场识别和前台检测文件。损坏的软件设置会先原样备份再恢复默认值；缺失的炉石日志配置会自动补齐并复查。无法修复的关键故障使用系统弹窗汇总原因和处理办法，并在创建主窗口前退出。炉石未启动、尚无对局日志、未授权录屏或暂时离线不属于启动故障，不会阻止进入软件。
- 二级工作台第一行是“权限管理”。当前只列真实需要的屏幕录制权限：已授权显示“正常”，其余状态显示“点击授权”。自动识别在任何截图前先检查权限，未授权时只发布错误，不调用截图，也不自动打开系统设置；系统请求只能由主窗口里的用户点击触发。
- 启动时检查并修复炉石 `log.config`，打开 Power/Zone/Decks/Arena 日志输出；修改前保留备份，自动验收进程不会触碰真实配置。
- 导入炉石卡组代码、炉石导出文本或手写卡组列表。
- 自动同步炉石“我的收藏 / 套牌”里的本机套牌，并写入软件数据库。
- 对局开始后优先读取 `Decks.log` 的已选套牌记录；无法直接确认时再根据真实抽牌/出牌日志自动匹配收藏套牌，不要求用户手动设置当前牌库。同一时刻由两条日志链重复输出的开局标记只算一次，不能把刚激活的套牌再次清空；嵌套写出的手牌区域变化也会计入剩余牌库。
- 增量日志游标只在本批完整内容处理成功后提交；临时处理失败时保留原位置并自动重试，界面推送失败与日志处理隔离，不能因此跳过或重放日志。
- 收藏记录的基础卡牌数量必须与当前 `Power.log` 的本方牌库快照一致；开局额外生成的牌会单独计入实时总数，不会阻止已选套牌识别。不一致时不允许旧套牌覆盖实战数据，而是显示真实牌库数量并等待精确匹配。
- 对局中被洗入或塞入本方牌库的新牌按实体去重计数；已知牌合并进对应卡牌数量，暂未揭示的牌显示为“被塞入的未知牌”，揭示后自动替换。重放完整日志时会区分开局生成牌和中途塞牌，避免重复统计。
- 监听中的炉石重开会创建新的日志会话目录；每次重新开始监听也会创建独立的内部会话身份，即使路径相同也不复用。旧日志读取、画面识别、评分请求和待确认竞技场牌库在提交前必须核对会话身份，不能污染新状态。如果最新会话暂时没有 `Power.log` 且没有可用竞技场牌库，服务会清空旧状态并读取 `LoadingScreen.log`：仍在登录、大厅、选牌或等待开局时显示“已识别炉石，等待开局”，只有已经进入 `GAMEPLAY` 仍没有 `Power.log` 才提示修复。自动发现若起初只命中孤立的根级 `Player.log`，后续允许重新扫描全部受支持的默认日志根，从另一目录恢复可用会话；用户手动指定的文件或目录始终锁定原文件或所在会话范围，不能扩展到默认日志根。后续检查不能因为先看到某个 `Decks.log` 或 `LoadingScreen.log` 就把范围绑死在该文件上；同会话或新会话的 `Power.log` 出现后应在下一次检查时自动恢复，不能回退显示旧会话牌库。同一个新 `Arena.log` 即使起初为空或暂不可用，后续在原路径写入可用内容也必须自动处理。日志文件变大只做增量读取，不能因为更新时间变化而整局重放。
- 竞技场选牌时读取 `Arena.log` 和 `Power.log`；当前版本不输出候选牌的国服客户端会按左、中、右三个固定位置识别炉石窗口内的牌名，排除卡牌正文和英雄皮肤等干扰后显示真实评分和胜率。暂时只认出两张时先按原位置显示，第三张继续识别并自动补齐。若首帧先绑定到同名旧编号，Firestone 数据加载后必须按牌名重新选择有统计的有效编号，不能让传说团队长期停留在“暂无”。传说团队按本次选择和两张附带牌合计三张；在游戏显示 29/30 时必须继续保持选牌状态和画面识别，不能提前进入完成状态。
- 标准/狂野/休闲选牌页会识别画面里的模式标题和右侧当前套牌名，用于在对局开始前把悬浮窗切到正确收藏套牌；休闲页只在牌名唯一对应一副本地套牌时启用。
- 冷启动时即使新会话暂时只有 `Decks.log`、还没有 `Power.log`，也会启动标准/狂野/休闲选牌页识别，不需要先进入竞技场来激活记牌小窗。
- 确认标准/狂野/休闲套牌后自动打开置顶小窗；`Power.log` 的 `GT_CASUAL` 开局按构筑记牌器管理。开局时保留刚确认的套牌，对局暂时无法精确识别时也保持“正在识别”小窗。进入竞技场时复用同一主小窗并切换内容。自动检测模式下，炉石不在前台时自动隐藏，返回炉石后恢复，不会抢走游戏焦点。
- 自动检测模式临时失焦时只隐藏我方和对手记牌窗，不销毁页面；返回炉石后直接恢复，避免截图、切换软件或短暂失焦后重建失败。总开关关闭、对应记牌器开关关闭、用户手动关闭或应用退出时才释放窗口。手动检测模式不接管用户手动打开的我方和对手小窗。主记牌窗位置和对手窗折叠意图都会保留。
- 标准/狂野模式同时驱动左侧天梯推荐窗，休闲模式不显示天梯推荐。主进程严格校验国服、版本、胜率、场次和卡组代码，只从当前版本且达到最低场次的记录中选择最高胜率卡组；没有可信来源时明确显示不可用。
- 新用户普通启动默认显示主窗口；只有用户主动开启“启动后自动最小化”才会隐藏。前台开关只决定启动、Dock、再次打开或托盘打开时是否把主窗口带到前面，不会让它常驻置顶，点击炉石或其他软件后会正常退到后面。
- 三个实战窗首次按“左二右一”布局：英雄胜率窗和对手记牌器在左，我方记牌器在右。升级前若对手窗还保存为紧贴屏幕最左边的旧位置，会先迁到英雄胜率窗右侧，避免重叠。三个窗口分别保存自己的位置和大小；设置里的位置、水平偏移和垂直偏移只调整我方记牌器。恢复时优先保留原副屏位置，显示器被移除或坐标越界时才夹回仍存在的可见区域，不按鼠标当前所在屏幕搬家。对手窗被拉高时，标题、行动方、回合、概览和公开计数保持固定高度，只有底部卡牌生命周期区域获取新增空间。
- 竞技场评分按版本缓存，只在首次使用或评分版本变化时更新；完成选牌后即使还没生成 `Power.log`，也会从 `Arena.log` 自动生成竞技场牌库。选牌、重选和等待开局时，右侧小窗只显示 Firestone 风格的“选取率 / 卡牌 / 影响”牌表；实际对局开始后该表完全退出并恢复普通记牌器。地下竞技场重选会保留全部新选择，并等待同一牌库的精确 `Decks.log` 决定最终 30 张；证据不足时明确显示已确认数和待识别数，不再伪装成完整牌库。
- 地下竞技场在点击“开始”前若 `Arena.log` 只提供 31–35 张候选快照，右侧小窗必须立即展示候选牌，并标明“候选 · 最终30”；只有收到准确的 30 张 `Decks.log` 后才能把它当成最终套牌。
- 竞技场评分缓存过期时先显示最后一份有效数据，后台再更新；同职业同卡牌的短暂缺字段更新不会清空已显示的选取率和胜率，换职业或换卡时不会继承旧数据。
- 进入竞技场后，左侧独立窗口显示 Firestone 当前版本英雄胜率排行；数据按 12 小时缓存，离线时保留旧排行并明确提示。离开竞技场、关闭总悬浮开关或关闭专用设置后窗口释放，手动关闭后本次竞技场不再自动重开。
- 从暴雪官方卡牌浏览器导入全量传统对战卡牌并缓存到本机数据库；保留 HearthstoneJSON 的卡牌编号映射用于日志匹配。官网页面脚本地址不变时，12 小时内可复用完整缓存；缓存过期或用户手动刷新时必须重新读取官方卡牌接口，防止同一脚本版本下的静默数据更新被漏掉。
- 主程序可从本机缓存分页浏览可收藏卡牌，按关键词、职业和类型筛选，并显示卡图与完整效果。
- 牌库、对手出牌和竞技场候选牌接入卡牌缩略图、法力值、攻击/生命、战吼/技能文本及关联牌详情。
- 持续到本局结束的出牌效果按明确卡牌编号进入双方隔离的“影响全局”区域；`JAIL_122`（米尔牢斯·法力风暴）属于本规则。同一实体的重复出牌块按实体编号去重，新对局和对局结束时清空。
- 卡牌详情优先显示官方固定关联；没有固定编号但正文明确写有“随机召唤固定费用随从”时，按本机卡库生成对应费用的可收藏随从候选。普通悬浮显示前 12 张，固定详情后分批查看完整候选；推断搭配牌并入关联牌，但理论候选与本局实际结果继续分区，避免把历史全卡库误报为当局精确结果。
- 卡牌详情会按真实日志补充本局动态目标；“决胜时刻”显示最后死亡的友方恶魔，并忽略对手死亡和同一事件的重复日志。
- “天定之灾克尔苏加德”的复活数量优先读取 `Power.log` 的动态计数；在该标签尚未出现时，按双方隔离统计本局已死亡的 `REV_845` / `CORE_REV_845` 作为可靠回退。新对局清零且可显示 0；详情正文和独立数量栏都显示真实值，不能依赖卡牌库中的空白占位文本。
- “超时空鳍侠”在首次完成换牌时冻结我方起始手牌；换掉的牌和幸运币不计入，重复牌保留，卡牌离手后仍能显示，新对局会清空旧快照。悬浮简介显示“我的起始手牌”，不再同时显示误导性的空“关联牌”。
- “匣中古神”等随机施法牌的详情会分别显示理论候选牌池与本次真实施放结果；双倍施放按真实张数记录，古神再次施放古神时保留嵌套层级，同一段日志的重复输出不会重复计数。
- 手牌已满时从牌库直接进入墓地的卡牌会从当前位置移除，并单独进入“疑似烧毁”历史；正常施放的牌进入“已使用”历史，不再混入“其他”。
- 主窗口支持手动打开我方小窗，以及展开或折叠对手小窗；具体恢复时机以自动/手动检测模式和下方关闭契约为准。
- 主窗口可最小化到 Dock；对手出牌可单独打开为独立置顶小窗。
- 根据日志里的区域变化统计我方抽牌、我方出牌、对手出牌。
- 只在 `Power.log` 能通过本地玩家 controller 确认 `PLAYSTATE` 时记录胜、负或平；最近 100 局保存在 Electron `userData/match-history.json`，主窗口显示胜率和最近对局。同一日志重放不会重复记录，无法确认归属的结果不会猜测。

## 窗口关闭和开关契约

- “悬浮窗总开关”关闭时，全部实战小窗和对手折叠入口立即关闭；之后切换模式、回到炉石或重启都不能自行恢复。
- 我方场攻、对手场攻、奥秘预测分别使用独立透明窗口；智能计数进一步按规则一项一个窗口。奥秘窗口的候选项以卡牌编号解析真实卡图，外部图片不可用时显示本地占位，不影响候选名称；候选使用 `124px` 宽、`17px` 行高的单列牌条，费用位于左侧窄栏，名称叠在横向卡图上，左上问号徽章占用额外透明窗口区域。问号和标题都可短按收起、展开或拖动窗口；折叠后真实窗口收成 `44×44`，整个区域均可操作，视觉问号仍为 `24×24`。奥秘窗、我方与对手场攻入口以及每个智能计数器分别保存位置，刷新、重启或显示器变化后按当前炉石屏幕恢复并留出边缘安全距离；奥秘折叠、展开保持同一左上锚点。只有奥秘问号、标题、场攻入口或智能计数圆片悬停操作时临时接收鼠标，短按、拖动结束和取消后恢复穿透；恢复失败会持续重试，快速重新移入不会被旧请求反向切回穿透。其余透明区域和奥秘候选始终穿透，不以滚轮换取对炉石点击的拦截。智能计数默认从我方场攻右侧开始排列，与场攻保持 `8px`、相邻窗口保持 `4px` 间距；空间不足时在当前工作区先向上、再向下换行。四类总设置互不捆绑，智能计数还支持当前相关规则的单项隐藏与恢复。窗口只在炉石前台显示。
- 拖动奥秘、场攻或智能计数小窗时，辅助窗前台和拖动会话都视为记牌器自身交互；主记牌器、对手记牌器与其它辅助窗保持可见。松手后保留短暂宽限，避免前台检测空值造成闪退；真正切换到其它应用后仍正常隐藏。
- 智能计数由可扩展规则库生成，不在追踪主流程逐张硬编码。己方按当前套牌自动激活，对手在关键牌实际出现后激活；详细规则和可信边界见 [智能计数规则库](./smart-counter-rules.md)。
- “我方卡牌记牌器 / 对手卡牌记牌器”是跨天梯和竞技场的全局开关。关闭对应开关时，展开窗和折叠入口立即关闭；重新开启只恢复该类窗口的正常管理，不改另一个窗口。
- 自动检测模式中，我方窗的关闭按钮抑制当前套牌或模式，真正切换套牌或模式后才允许自动重开。手动检测模式中，后台不会因为炉石失焦、监听状态或模式变化关闭用户手动打开的我方、对手窗；总开关和对应全局开关仍有最高优先级。
- 对手窗的关闭按钮只折叠为 `52×38` 入口。奥秘更新、后台恢复和炉石重新回到前台只能无焦点显示这个折叠入口，不能自动展开；只有点击折叠入口或主窗口的对手小窗按钮才展开。
- 英雄胜率窗手动关闭后，本次竞技场不再自动打开；离开该次竞技场后解除抑制。总开关和“竞技场英雄胜率排行”开关会立即关闭该窗。

## 发布物

- 唯一保留的安装包路径是 `outputs/炉石记牌器.app`。
- 唯一保留的压缩包路径是 `outputs/炉石记牌器-mac-arm64.zip`。
- `npm run package:mac-arm64` 每次都会覆盖这两个固定路径，并清理旧的 `release-*`、历史应用副本和历史版本压缩包；`outputs/release-verification` 验收证据目录会保留。
- 每次替换 `/Applications/炉石记牌器.app` 前必须先把应用补丁版本增加一位，例如 `0.4.2` 更新为 `0.4.3`；安装包、锁文件和应用内版本保持一致。
- 版本第三段只使用 `0` 到 `9`；例如 `0.5.9` 的下一版是 `0.6.0`，不能写成 `0.5.10`。
- macOS 包使用固定标识 `cc.acyg.hearthstonemactracker`，并长期保持同一 Developer ID 团队与签名类型，避免系统录屏权限因为代码身份变化而失效。若历史 Apple Development 包已经留下授权，升级到 Developer ID 包时必须关闭再开启该项权限，并彻底重启软件。

- 安装包 `Info.plist` 必须包含 `NSScreenCaptureUsageDescription`，说明画面只用于本地识别模式、套牌和竞技场候选牌；缺少该声明的包不得发布。
- 安装包只收录构建结果、主进程结果和正式运行依赖；打包时自动拒绝源码、测试、文档、样例日志、截图和开发缓存。
- 发布验证只跟踪并清理本次启动的测试进程；脚本正常结束、失败或被中断时都必须回收该进程，普通退出无响应时在限定等待后强制结束，禁止用全局进程名误杀用户正在运行的记牌器。卡牌预览小窗使用独立样式，不得注入主窗口整套样式；验收发现可见 CSS 源码时直接失败。
- macOS 上所有运行实例都使用普通应用模式并保留 Dock 运行指示；自动验收不得切换辅助应用模式或主动隐藏 Dock。验收结束后仍需确认测试进程为零；正式程序仍运行时，固定入口下方的运行指示必须保持可见。
- 悬浮窗切换桌面或全屏可见性时必须跳过应用类型转换；同一配置只应用一次。Electron 默认转换会短暂隐藏窗口和 Dock，禁止在运行期使用。
- README 截图由 `npm run screenshots:readme` 从当前源码重新构建。每个场景使用系统临时目录、脱敏日志、清理后的 `QA_*` / `NODE_*` / `VITE_*` 环境和独立进程组；30 秒超时后先正常结束，再强制清理本组进程。
- 截图生成必须验证本地页面、安全接口、零界面报错、Dock 运行指示可见、固定尺寸、临时日志路径、零继承 `NODE_*`、零横向溢出和 PNG 无文本元数据。四个场景全部通过后才整套替换 `docs/screenshots/`；检查 JSON、日志、环境和用户数据不得进入公开目录。

## v0.3.11 运行边界

- renderer 接收的牌库、事件、统计、卡牌详情和生命周期状态必须先通过运行时校验。非法实时更新保留最后一次有效状态，不得阻断稍后返回的合法初始化；后续合法实时更新可清除本次校验错误。
- 正式包页面加载、开发地址限制和日志游标提交规则属于发布契约，不能由单个辅助窗口或单条日志类型绕过。

## v0.3.12 身份与牌组证据边界

- 同一实体的分行快照标签必须先合并再判断归属，`ZONE` 与 `CONTROLLER` 的到达顺序不得改变本方初始牌库结果。
- 本方 controller 未确认时，带 controller 的区域变化只能暂存；获得完整玩家证据后按原顺序处理，不能把“尚未证明是本方”当成“已经证明是对手”。
- 活跃竞技场收到更精确的牌组时，只原位对账基础牌组并迁移可唯一对应的同卡记录；不得重置对局、回合、实体、手牌、对手记录或比赛统计。
- 推断式收藏套牌匹配至少需要两张不同的本方已观察卡，并要求最佳候选唯一或严格领先；炉石显式选中的套牌不受该推断门槛影响。

## v0.3.13 竞技场统计边界

- Firestone 职业单卡缓存保存抽到和带牌的原始计数；派生影响按职业总体胜率重算，不持久化为唯一事实。
- 缓存 schema 缺少抽到统计时判为可读但过期，后台刷新；网络不可用时仍可用新缓存的原始计数重算。
- renderer 只接受数值评分字段。抽到影响、对套牌影响、选取率或高胜选取率缺失时显示“暂无”，不得用 HearthArena 评分、出牌胜率或其它桶替代。
- 高胜率标签来自 Firestone 实际胜场桶。6 胜桶显示“6+胜选取率”；其它桶保留实际门槛。

## v0.4.1 可靠性边界

- 套牌识别必须公开来源和证据状态；多个候选或观察不足时不装载候选牌库，详细文案见 [套牌识别 UI/体验规范](./deck-identification-ux.md)。
- 卡牌与竞技场评分主缓存采用校验后原子替换并保留一份有效备份；正式缓存损坏时自动回退。
- 竞技场画面识别以日志为先；模糊结果连续两次一致才采用，三个位置独立稳定，完整结果不被不完整帧降级。
- 应用运行标记只保存版本、时间和阶段；异常退出只写入本地诊断日志，不保存玩家、套牌或日志正文。
- 完整实现范围和验收标准见 [v0.4.1 可靠性强化](./reliability-hardening-v0.4.1.md)。

## v0.2.9 卡牌生命周期

- `TrackerEngine` 是单局卡牌位置和动作历史的唯一事实来源；used 只有一套可修改记录。
- 当前区域与动作历史是两类视图，不能相加推算总数。烧毁只在日志确认十张可计数手牌且卡牌从牌库直接进入墓地时标为“疑似烧毁”。
- 随机施法结果按本次 `usageId` 绑定，不按牌名或 `cardId` 汇总。双倍施放、重复法术、回手再用和古神套古神都保留各自顺序与层级。
- 奥秘槽位数量和每个槽位的候选数量分开计算。每个对手奥秘槽独立保存日志明确给出的职业；该职业优先于对手英雄职业生成候选，缺失时才回退到英雄职业。新对局必须清除上一局职业，跨职业奥秘不能污染其它槽。
- renderer 只读取必填的 `cardTracking`；旧共享字段保留一个版本供非 renderer 兼容。

## v0.3.0 对局流程与牌库插入

- `MatchFlow` 统一维护回合、行动方和双方本回合法力，日志缺字段时省略，不推测。
- `cardTracking.contextDetailsBySideAndCardKey` 按双方隔离投影球等单局动态详情。
- `cardTracking.deckInsertions` 独立发布来源剩余数量与置顶、置底位置，普通牌库行仍是牌名与数量的唯一列表。
- `DISPLAYED_CREATOR` 关联来源，离开牌库实时减少来源数量；`SHUFFLE_DECK` 只使位置失效。

## v0.6.9 总血量上限计数器

- `TrackerEngine` 只把英雄实体的 `HEALTH` 作为总血量上限事实；`DAMAGE`、回血和 `ARMOR` 不参与。
- `PublicTrackerState.heroHealthLimit` 按我方、对手隔离发布；身份或英雄类型证据不足时省略，不猜数字。
- 双方计数器使用独立辅助窗口、独立位置和同一套安全拖动协议。
