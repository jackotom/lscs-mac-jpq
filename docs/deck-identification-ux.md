# 套牌识别 UI/体验规范

## 完成标准

- 主窗口和我方悬浮窗使用同一套状态，不再把所有结果都叫“已自动识别”。
- 普通玩家只看到“从哪里找到、现在是否确定、下一步做什么”，不需要理解日志、置信度、阈值或匹配分数。
- 五种套牌状态都有固定文案；加载和失败只作为临时覆盖状态，不再增加套牌状态。
- `100px` 宽悬浮窗仍能看到套牌名和文字状态，不依赖颜色点，不产生横向滚动。
- 未确认套牌时不显示旧套牌，不把未知牌库写成 `0`，不从多个候选中擅自挑一套。

## 当前界面问题

- 主窗口“当前套牌”只有有内容和空状态两种表达，空状态统一写“尚未识别当前套牌”，玩家不知道软件是在查找、等待，还是已经失败。
- 主视觉只要进入对局就可能显示“牌库剩余 0 张”，无法表达“牌库数量还不知道”。
- 悬浮窗把日志确认、画面确认和对局推断都合并成“已自动识别”，无法说明结果来自哪里。
- 悬浮窗的“读取中 / 读取失败 / 等待识别 / 识别中 / 不可用”互相重叠，同一件事可能出现不同叫法。
- `100px` 窄窗会把顶部状态压成只有颜色的小点；套牌摘要只剩一行，状态详情只能靠悬停看到。
- 当前公开状态只有已匹配套牌编号，没有确认来源和候选数量；内部虽然区分炉石记录与画面识别，但界面拿不到，对局推断也没有单独来源标记。

## 五种套牌状态与固定文案

下表中的“内部状态名”用于开发和验收，不直接显示给玩家。

| 内部状态名 | 进入条件 | 主窗口“当前套牌” | `100px` 悬浮窗套牌区 | 牌库内容 |
| --- | --- | --- | --- | --- |
| 日志确认 | 炉石明确给出当前选择的收藏套牌，且牌表校验通过 | 标题显示套牌名；状态固定为“炉石已确认这套牌” | 第一行套牌名；第二行“炉石确认” | 显示确认牌表 |
| 画面确认 | 选牌页画面唯一找到当前套牌，且模式与收藏套牌一致 | 标题显示套牌名；状态固定为“已从游戏画面找到” | 第一行套牌名；第二行“画面找到” | 显示确认牌表 |
| 推断匹配 | 根据本局已出现的我方卡牌得到唯一可用结果 | 标题显示套牌名；状态固定为“已根据本局卡牌匹配” | 第一行套牌名；第二行“本局匹配” | 显示匹配牌表 |
| 多个候选等待 | 已有信息能找到两套或更多可能套牌，但还不能唯一确定 | 标题固定为“还不能确定是哪套”；说明固定为“可能是 N 套；继续对局后会自动确认。” | 第一行“还不能确定”；第二行“N 套可能” | 不显示任何候选套牌的牌库行；可保留已公开的真实手牌、场上和历史 |
| 无证据等待 | 尚未得到可用于识别当前套牌的信息 | 标题固定为“等待套牌信息”；说明按当前场景显示下方三句之一 | 第一行“等待套牌”；第二行显示当前场景短句 | 不显示旧套牌；牌库数量显示 `?`，不能显示 `0` |

无证据等待的主窗口说明只能使用以下三句之一：

- 选牌页：“停留在选牌页，记牌器会自动查找。”
- 已开局：“继续对局，出现更多卡牌后会自动查找。”
- 尚未开局：“进入选牌页或开始一局后会自动查找。”

无证据等待的悬浮窗第二行对应使用“进入选牌页”“继续对局”“等待开局”。

## 加载表达

加载不是第六种套牌状态，只在一次真实查找正在进行时临时覆盖套牌区。

- 主窗口标题：“正在查找套牌”
- 主窗口说明：“正在读取炉石当前信息…”
- 悬浮窗第一行：“正在查找”
- 悬浮窗第二行：“请稍候”
- 同时显示放大镜或转动指示，并保留可见文字；系统开启“减少动态效果”时停止转动，但文字不变。
- 查找结束后必须进入五种状态之一。没有任务在运行时不能一直显示加载动画。

## 失败表达

失败不直接展示内部报错。主窗口给出一句原因和一步处理方法；窄悬浮窗只给出短原因与处理入口。旧套牌和旧统计同时清空。

| 场景 | 主窗口固定文案 | `100px` 悬浮窗固定文案 |
| --- | --- | --- |
| 无法读取对局信息 | “无法读取对局信息” / “点‘修复日志’，重启炉石，再开始一局。” | “无法读取信息” / “请修复日志” |
| 没有屏幕录制权限 | “无法查看炉石画面” / “在系统设置中打开‘屏幕录制’，再重新打开记牌器。” | “无法查看画面” / “请查看设置” |
| 没有可匹配的收藏套牌 | “没有可匹配的收藏套牌” / “打开‘我的收藏 → 套牌’，再回到记牌器读取。” | “没有收藏套牌” / “请先读取套牌” |
| 套牌状态读取失败 | “套牌状态读取失败” / “关闭并重新打开记牌器。” | “读取失败” / “请重开软件” |

- 主窗口可提供“查看详情”，内部错误只放在详情中。
- 悬浮窗不显示文件路径、英文错误、错误编号或长句，不把原始报错塞进标题属性代替可见提示。
- 可以自动恢复的短暂失败显示“正在重新查找”，恢复后自动回到对应套牌状态，不反复弹窗。

## 主窗口显示规则

- “当前套牌”卡片固定顺序为：套牌名或状态标题、状态说明、卡牌统计或下一步操作。
- 五种状态要与主视觉一致。套牌未确认时，主视觉可以写“对局正在记录”，说明只能写“套牌仍在确认中”，不得展示“牌库剩余 0 张”。
- 多个候选时可在主窗口额外列出最多三个套牌名，格式为“可能是：冰霜法、元素法等 3 套”；悬浮窗不列候选名称。
- 状态变化只更新“当前套牌”卡片，不让整页跳动。确认同一套牌但来源升级时，只替换状态说明。
- 需要玩家处理时显示一个与说明同名的按钮：“修复日志”“打开设置”“读取收藏套牌”或“重新打开软件”。

## 窄悬浮窗显示规则

- 套牌区改为两行：第一行只放套牌名或状态标题，第二行只放四到六个汉字的状态；手牌数和牌库数仍固定在右侧。
- 第一行和第二行都单行省略。套牌名可省略，状态文字不可全部隐藏。
- `100px` 宽时不增加徽章、候选列表、来源长句或横向滚动；最小高度 `200px` 时仍保留这两行。
- 顶部服务状态即使继续使用颜色点，套牌状态也必须有可见文字。任何状态不能只靠绿、黄、红区分。
- 已确认使用“勾 + 文字”，等待使用“时钟 + 文字”，失败使用“警告三角 + 文字”。图形和文字同时存在；图形不代替文字。
- 多个候选和无证据等待均显示牌库 `?`。只显示日志已经确认的手牌、场上、墓地等事实，不拼接候选套牌内容。
- 屏幕阅读器读出完整句子，例如“冰霜法，已从游戏画面找到”；状态变化使用礼貌播报，失败使用警报播报。

## 状态切换规则

- 可信来源优先级固定为：炉石明确确认、游戏画面唯一确认、本局卡牌推断。
- 更高优先级确认同一套牌时直接升级说明，不经过加载，不闪空白。
- 更高优先级确认另一套牌时立即替换旧牌表，并显示一次“套牌已更新”；低优先级结果不能覆盖高优先级结果。
- 候选从多套缩到一套后直接进入推断匹配；候选再次变多时退回多个候选等待，并清空之前候选牌表。
- 新对局、模式切换或真正切换套牌时先清空旧套牌，再进入加载或等待；不能让上一局套牌留在新状态下面。

## 实现前置数据

界面至少需要得到以下信息，缺一项就不能完整验收：

- 当前五种状态。
- 已确认套牌名称和编号。
- 确认来源：炉石记录、游戏画面或本局卡牌推断。
- 候选数量；主窗口如需展示候选名，再提供最多三个名称。
- 当前是否真的正在查找。
- 失败类别和对应处理动作，不直接传整段原始报错给悬浮窗。

当前仅有的已匹配套牌编号不足以区分前三种确认方式；现有内部来源信息需要安全地传到界面，对局推断和候选数量也需要补齐。

## 可验收清单

- 用五组固定状态分别打开 `1400px` 主窗口、`900×620` 主窗口、`100×900` 悬浮窗和 `100×200` 悬浮窗。
- 日志确认显示“炉石已确认这套牌 / 炉石确认”，画面确认显示“已从游戏画面找到 / 画面找到”，推断匹配显示“已根据本局卡牌匹配 / 本局匹配”。
- 两个候选时显示“还不能确定是哪套 / 2 套可能”，不出现任一候选的完整牌库。
- 无证据时显示“等待套牌信息 / 等待套牌”，牌库数为 `?`，旧套牌和旧统计不可见。
- 加载只在真实查找期间出现；结束后不残留“正在查找”。
- 四类失败逐一显示固定原因和固定处理方法，悬浮窗没有路径、英文错误或超长文字。
- 关闭颜色或使用灰度截图后，仍能凭图形和文字分清确认、等待和失败。
- 最长套牌名、两位数候选数量和三位数统计下，`100px` 悬浮窗无横向滚动，状态文字仍可见。
- 键盘和屏幕阅读器能读出完整状态；状态变化不会抢走炉石焦点。
