# Mac 记牌器 UI/体验说明

## 完成标准

- 首屏就是工具本体，不做官网式介绍页。
- 深色界面要有层次：背景、顶部栏、指标、面板、列表行不能糊成一块。
- 1280x760 正常舒展，900x620 仍保持三栏可用。
- 顶部状态、日志按钮、手动导入兜底按钮、开始/暂停按钮要一眼分清。
- 事件流和牌库列表保持高密度，但时间、事件、牌名、数量不能挤在一起。
- 竞技场面板要同时显示当前三选一、评分、选牌进度和已生成牌库；评分不可遮挡牌名。
- 缺少 `Power.log` 或只看到 `Player.log` 时，主界面和小窗都先提示“先点修复日志，然后重启炉石/开始一局”，不要展示默认示例卡组。

## 当前结构

现有入口 `src/renderer/main.tsx` 已引入 `src/renderer/styles.css`，主界面样式目前由 `App.tsx` 内的桌面工具样式覆盖。当前页面结构是：

```tsx
<main className="app-shell">
  <header className="top-bar">
    <section className="brand-block">标题和日志路径</section>
    <section className="status-strip">状态</section>
    <nav className="top-actions">日志 / 卡组 / 开始</nav>
  </header>

  <section className="dashboard-grid">
    <aside className="panel deck-panel">我方牌库</aside>
    <main className="panel event-feed">实时事件</main>
    <aside className="panel opponent-panel">对手记录</aside>
  </section>
</main>
```

## 类名约定

- 外壳：`app-shell`
- 顶部：`top-bar`、`brand-block`、`brand-mark`、`status-strip`、`top-actions`
- 状态：`status-dot`，状态类为 `status-ready`、`status-tracking`、`status-paused`、`status-offline`
- 按钮：普通按钮、`primary-action`
- 主工作区：`dashboard-grid`
- 面板：`panel`、`deck-panel`、`event-feed`、`opponent-panel`
- 牌库/对手列表：`card-list`、`deck-card-row`、`played-list`
- 事件流：`timeline`、`timeline-row`、`actor-me`、`actor-opponent`
- 卡组工具页：`deck-tools-page`、`deck-tools-workspace`、`collection-import`

## 小窗口策略

### 主窗口启动与前台行为

- 主窗口创建前先完成启动检修。检查全部通过时静默启动；自动修复成功时不增加打扰，只写入本机诊断记录。关键故障无法修复时使用 macOS 系统错误框显示“启动检修未通过”、故障项、简短原因和处理办法，只提供明确的“退出软件”，不能进入残缺主界面。
- 炉石未启动、尚无 `Power.log`、只在大厅或选牌页、未授权屏幕录制、网络暂时不可用都不属于启动阻断条件，继续按现有等待、权限和离线提示处理。
- 新用户普通启动默认显示主窗口。只有用户主动开启“启动后自动最小化”，之后启动时才隐藏主窗口。
- “设置 → 基础设置 → 打开软件时将主窗口带到前面”只控制启动、Dock、再次打开或托盘打开时，是否把主窗口一次性带到前面。关闭时主窗口仍会显示，但不抢当前软件焦点。
- 这不是常驻置顶。用户点进炉石或其他软件后，主窗口必须正常退到后面，不能持续抢焦点。
- 该设置不改变记牌器、英雄胜率等实战小窗的置顶和显隐规则。

### 左侧天梯推荐

- 标准模式显示标准推荐，狂野模式自动切换狂野推荐；竞技场和未知模式隐藏。
- 默认约 `100x900`，贴显示区域侧边；炉石离开前台时隐藏，恢复时不抢焦点。
- 胜率、场次和代码必须来自同一条当前版本记录。配置国服数据源时明确标记国服；否则显示 Firestone 国际服的标准/狂野、传说分段、最近一周且至少 800 场数据，并显示来源、更新时间和样本量，不能把国际服冒充国服，也不能用旧版本顶替。
- 牌表内部滚动，复制按钮固定底部；复制成功显示“已复制”，失败明确提示。

- 标准/狂野选牌页确认当前套牌后立即自动出现记牌小窗，不等待进入对局；牌库行必须同时显示真实费用和缩略图，不能因为此时尚无 `Power.log` 而退化成 `?` 和空白图。
- 进入竞技场后，同一个主记牌小窗自动切换为竞技场内容；标准、狂野和竞技场不能同时显示多个主小窗。
- 从标准/狂野切入竞技场时，竞技场日志一旦确认当前牌库，必须立即替换旧的构筑套牌，不得继续显示标准模式卡牌。
- 自动检测模式下，炉石不在前台时只隐藏主小窗和对手小窗，不销毁窗口；返回炉石后使用不抢焦点的方式直接恢复。手动检测模式不允许后台因此关闭用户手动打开的我方或对手小窗。
- 只确认模式但未确认套牌时显示“正在识别套牌”，统计、牌库、抽牌和对手数据全部清空，不沿用旧内容。
- 已进入普通对局但牌库仍未精确匹配时，小窗继续显示“等待识别”，不能直接消失。
- 普通对局出现“剩余牌数大于零但没有任何牌库明细”，或生命周期区域计数明显不一致时，小窗显示“牌库数据异常，正在重新识别”。原始计数必须保留，界面不能隐藏、改写或猜测卡牌；正常空牌库和竞技场状态不提示。
- `Player.log` 已确认开局但 `Power.log` 停更时，小窗必须继续显示并提示重启炉石恢复日志；不得沿用旧局牌库伪装正常记牌。
- 自动检测模式中，用户关闭我方窗后，本套牌保持关闭；真正切换套牌或标准/狂野/竞技场模式后恢复自动显示。手动检测模式关闭后，只能由用户再次打开。
- 普通启动显示主窗口；实战小窗沿用各自上次位置和大小。
- 拖动或缩放任意一个小窗时允许短暂失去焦点，但左右两个小窗都不能消失；两个小窗共享交互保护，主窗口里的“小窗”按钮必须恢复已隐藏窗口，不能误当成关闭。
- 录屏权限被拒绝或识别失败时，小窗明确显示失败原因，并清空旧套牌内容。
- 首次需要自动识别时只请求一次 macOS 录屏权限；用户在系统设置中开启并完成 Touch ID/密码确认后，重启记牌器生效。本次运行不能重复弹出授权窗口。
- 外层固定一屏，滚动只发生在 `card-list` 和 `event-list` 内。
- 900x620 时仍保留三栏，不退成单列。
- 指标卡高度压低，列表行约 27-30px，事件行约 27-30px。
- 牌名、日志路径、事件内容都单行省略，避免撑破布局。

## 收藏套牌导入规则

- 卡组工具一级页面保留“粘贴卡组”和“从收藏读取”两条路。
- 日常主流程是后台自动同步收藏套牌并自动匹配当前对局；手动导入只是兜底。
- “从收藏读取”要用小白能看懂的短提示：如果没读到 Decks.log，先打开炉石，进入“我的收藏 → 套牌”，让游戏生成收藏套牌日志后再回来读取。
- 小高度窗口里卡组工具页不能横向溢出；收藏套牌列表和粘贴框内部滚动，导入按钮必须始终可点。

## 实战置顶小窗

实战小窗服务对局中快速扫一眼，不承担完整管理功能。我方默认尺寸为 `100x900`，允许缩到 `100x200`；屏幕高度不足时贴合可用高度，卡牌主内容独立滚动。

- 竞技场英雄胜率窗默认采用截图里的窄长比例 `100x560`，允许纵向缩到 `100x200`；标题栏除关闭按钮外均为清晰拖动区域，窗口四边可缩放。
- 拖动或缩放英雄胜率窗时，即使炉石短暂失去前台焦点，窗口也不能被隐藏或释放；交互结束后继续按竞技场和炉石前台状态管理。
- 英雄胜率窗在 `100px` 宽时使用紧凑三列，保留排名、英雄名和胜率，长英雄名单行省略，收起场次和职业副标题；缩到 `200px` 高时收起标题副说明，排行在窗内滚动，标题和关闭按钮始终可见。
- 英雄胜率窗移动或缩放后保持在当前显示器可见区域；手动关闭后本次竞技场不再自动重开，离开竞技场后解除该抑制。
- 首次创建采用“左二右一”：英雄胜率窗贴显示区域左边；对手记牌器默认约 `250x170`，放在胜率窗右侧并留 `24px` 间距；我方记牌器贴显示区域右边。
- 升级前若对手记牌器仍保存为紧贴最左边的旧位置，首次恢复时自动移到英雄胜率窗右侧，避免两个窗口重叠。
- 三个窗口分别保存位置和大小。有效的副屏位置优先保留，不能因为鼠标移到主屏就搬家；副屏被移除或保存坐标已经越界时，才夹回仍存在的可见区域。
- 设置里的“我方记牌器位置 / 我方水平偏移 / 我方垂直偏移”只调整我方记牌器。对手记牌器和英雄胜率窗只使用各自保存的位置，不能被这三项设置叠到我方窗上。
- 我方窄窗顶部固定为“记牌器、状态、打开软件设置、关闭”；在 `100px` 宽度下保留标题文字、齿轮和关闭操作，键盘焦点必须可见。
- 右侧设置页内的“我方卡牌记牌器 / 对手卡牌记牌器”是全局开关，不再区分天梯和竞技场；关闭后，对应展开窗和折叠入口都立即关闭，切换模式或重启后也不能自行恢复。“悬浮窗总开关”关闭时，全部实战窗和折叠入口都立即关闭。
- 对手记牌器分为“当前位置 / 历史”两页；当前位置包含牌库、手牌、场上、奥秘、墓地、移除，历史包含疑似烧毁、已使用。真正未知的手牌只显示一行“未公开 ×N”，已经公开过并返回手牌的牌继续显示真实牌名。只有日志给出唯一可靠关联时才能继承身份，不能按数量猜牌；未知牌库不伪造成已知卡牌。
- 区域总数已知时直接显示真实总数，即使其中卡牌名称尚未公开；只有总数未知且确认了部分卡牌时才显示 `≥N`，完全未知显示 `?`，禁止出现误导性的 `≥0`。
- 我方已开局但尚未拿到可信牌库总数时，牌库摘要显示 `?`，分组显示“待识别”；不能把未知显示成真实 `0`。正在识别、识别失败分别显示“识别中”“不可用”，已经识别且真正抽空时仍显示 `0`。

- 普通对局小窗采用贴边高密度竖表：工具栏约 22px、套牌摘要约 25px、分组标题约 21px、卡牌行约 22px；费用、横向卡图牌名、数量固定同一行。
- 普通对局小窗的信息顺序固定为“工具状态 → 套牌名/手牌数/牌库数 → 当前位置/历史 → 分组 → 单卡费用/牌名/数量”，只允许主内容区域滚动。
- 竞技场完成选牌后，牌库摘要同时显示“剩余/总计”（例如起手后 `27/30`），避免把剩余数量误认为只识别到 27 张。
- 竞技场证据不完整时，摘要显示“已确认 N/30”，并在滚动列表上方固定显示“N 张待识别”；未知项不能伪装成普通卡牌。只有精确确认 30 张时才显示 `30/30` 且隐藏警告。

- 外壳使用 `.overlay-shell`，深色半透明、轻边框、轻模糊，背景透明窗口内只露出工具面板。
- 顶部使用 `.overlay-header`，高度控制在 32-38px，支持拖动，只放标题、当前状态和极短路径/同步信息。
- 我方牌库使用 `.overlay-deck-list`，紧凑尺寸下列表行约 23px、缩略图 20x25；费用、牌名、剩余数量必须同屏可扫，长牌名单行省略。
- 对手小窗按生命周期分组；奥秘在独立“奥秘”组按真实槽位显示，候选开关只影响候选文字，不影响当前槽位数量。每个候选都可悬停或键盘聚焦查看卡牌效果，“可能 / 已排除”状态保持可见；没有卡牌资料时不弹空详情。疲劳、尸体和全局效果继续使用独立的紧凑计数。
- 对手出牌窗手动折叠后显示 `52×38` 入口；入口和主窗口里的“小窗”按钮都能恢复原尺寸，折叠/恢复状态以主进程为准。新增奥秘、炉石回到前台或后台恢复只能更新并无焦点显示折叠入口，不能自动展开。设置里关闭“对手卡牌记牌器”时必须连入口一起关闭。
- 新用户普通启动默认不显示场攻悬浮按钮，避免遮挡游戏；用户主动开启后，场攻只显示为英雄旁约 `32×32` 的“小剑 + 数字”，透明画布不能带边框、底板或大块操作区。
- 缺少 `Power.log` 或只有 `Player.log` 时，小窗只显示修复步骤，不显示剩余牌库、抽牌或对手出牌。
- 紧凑尺寸下隐藏非必要副标题、收紧行高和缩略图；放大窗口时才增加行高和留白，不改变信息结构。
- 滚动只允许发生在牌库和对手列表内部；小窗本体不能出现整页滚动。
- 竞技场选牌、重选和等待开局阶段，主记牌小窗只显示火石式三列牌表：“选取率 / 卡牌 / 影响”，阶段栏依次显示“选牌中 / 重选中 / 等待开局”；进入对局后立即切回普通记牌界面，不继续显示这两列数据。
- 三列牌表不显示单卡评分。选取率 `>=70%` 为绿色、`<=30%` 为红色、中间为黄色；卡组影响正数为绿色、负数为红色、零或缺失为黄色，固定两位小数且正数不加加号。
- 三列牌表保持深蓝黑底、费用和横向卡图同行；`100px` 窄窗不加宽、不产生横向滚动。
- 地下竞技场进入“重选新卡牌”时保留全部已确认保留牌和随后五次新选择，状态显示“重选中”，每轮重新显示三张候选牌的质量和评分；最终剔除结果不明确时等待精确牌库，不猜牌。回到标准/狂野选牌页后连续确认两次当前套牌再切换，避免残留竞技场内容。
- 识别到竞技场三选一时，自动在三张游戏卡牌下方显示透明数据条，每张候选牌固定三格：评分、选取率/胜率、高胜选取；HearthArena 官网简中/繁中数据只作为评分，不叫胜率；只有公开源明确提供 12 胜分桶时，第三格才显示 `12胜率`，没有高胜分桶时显示 `高胜数据`。数据条鼠标穿透，不能阻挡炉石选牌；离开三选一后自动隐藏。
- 传说团队等长牌名允许在唯一最佳结果下容忍多处画面识别错字；任一牌名识别失败不能伪造数据。选牌和重选阶段顶部状态显示“监听中”，不能写成“等待开局”；右侧牌库尚为空时显示“当前牌库尚无已选牌”，避免与三张候选识别混淆。
- 有卡牌资料的行使用 34x42 左右的缩略图；鼠标悬停弹出完整卡牌预览，显示费用、攻血、战吼/技能文字和生成/关联牌。置顶小窗里的预览要通过独立透明小窗向外展开，不能挤在牌库列表内部，也不能把置顶小窗本体撑宽；鼠标离开、窗口失焦或悬停刷新中断后必须自动收回，不能常驻在桌面上。
- 点击、滚动或拖动记牌器使“炉石记牌器”成为前台后，悬停详情仍必须正常出现；左右记牌器快速切换悬停时，旧窗口的延迟隐藏不得关闭新窗口的详情。切到其它软件后仍立即隐藏。
- 悬停或键盘聚焦一张牌时，当前牌继续用蓝色表示，同组和跨组的配合牌用暖金底色、左右 `2px` 内描边、弱内高光和 `配` 标记表示，不只依赖颜色。在 `100px` 宽度下仍保持 `20px` 行高，标记要避让数量角标，不压暗无关卡、不产生横向滚动；移开或失焦后立即恢复。
- 卡牌预览可用 `Option+Q` 固定或取消固定；固定后可将鼠标移入详情窗并滚轮查看长正文和关联牌。切换到炉石之外的应用时必须立即解除固定并隐藏，返回炉石后需要重新悬停，不能自行恢复。
- 关联牌没有图片时仍保留名称和效果文字，不因缺少衍生牌图片而显示空白区域。
- 随机施法牌的详情必须明确区分“理论候选牌池”和“本次实际施放”；标题显示总张数，实际结果保留重复牌和真实顺序，古神套古神使用金色层级线表示归属。
- 理论候选池很大时先显示首批内容，并提供“继续显示”按钮；实际施放的 5 张、双倍 10 张或更多结果始终完整显示。
- 禁止大圆角、大卡片、营销式标题、网页式分区说明和大面积装饰渐变。

## v0.3.13 竞技场候选四格数据条
