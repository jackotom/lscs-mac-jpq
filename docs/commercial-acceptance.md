# 商业版交付标准

这不是演示版的完成标准。每次准备发布前，主控都要按下面的闭环验收。

## 对局准确性

- 只在确认新对局和本地玩家身份后开始记牌。
- 对手的抽牌、出牌不能因为和我方同名而进入我方牌库。
- 重启软件、切换日志目录、日志截断或开始下一局后，上一局的牌库和事件不能残留。
- 收藏套牌自动匹配要有明确的成功、等待和失败状态，不能静默选错套牌。

## 竞技场完整性

- 优先使用 Arena.log，Power.log 只作有边界的兜底。
- 只识别真正的竞技场选牌，发现牌、换牌和普通对局选择不能误计入。
- 候选牌、评分、卡图、卡牌文字、生成牌和当前竞技场牌库都能在主窗口和小窗查看。
- 对当前版本未写出候选牌的竞技场日志，在用户已允许 macOS 屏幕录制后，必须能从可见的炉石窗口识别三张候选牌；未识别完整时不得显示猜测结果。
- 竞技场结束后必须回到普通对局状态，不污染下一局。

## 数据和更新

- 卡牌、衍生牌和评分都保存在本机版本化缓存中。
- 正常打开和悬停卡牌不能临时抓网页。
- 更新失败时继续使用最后一份有效缓存，并明确提示用户数据时间。
- 缓存损坏、网络中断和上游字段变化都有可读错误，不得静默显示空数据。

## 用户体验

- 首次打开能看懂下一步，不要求用户先理解日志文件。
- 首次画面识别只弹一次录屏授权；完成系统设置和 Touch ID/密码确认、重启应用后不再重复询问。未授权时不得继续显示旧竞技场或旧构筑套牌。
- 监听、暂停、缺日志、读取失败和更新失败都有明确状态。
- 小窗始终置顶、可拖动、窄窗口不裁切；卡牌行悬停显示完整卡牌预览。
- 中文长牌名、英文长牌名和无图衍生牌都不能破坏布局。

## 发布验证

- 发布前在 Apple Silicon Mac 上运行 `npm run verify:release`；任何一步失败都不得交付。
- Mac App Store 包另运行 `npm run verify:mas-arm64`。普通包的验证结果不得代替 MAS sandbox、签名、产物或启动结论。
- MAS 验收写出脱敏 manifest，只记录 commit、版本、Info.plist 哈希、sandbox/signature/pkg 与运行检查结果；不记录证书、profile 内容或账号信息。
- 自动验收证据保存在 `outputs/release-verification`，包括三类日志回放结果、主窗口与全部悬浮窗截图、检查数据和启动耗时。
- 发布门禁只运行一次完整 `npm test`；签名打包阶段完成原生组件、类型检查和正式构建，避免对未改代码重复运行测试或构建。
- 安装包必须使用稳定 Apple 开发签名并通过 `codesign --verify --deep --strict`；临时签名包不得作为交付物。
- 安装包必须通过 `plutil` 验证 `NSScreenCaptureUsageDescription` 存在，首次授权后重启应用并实测屏幕识别成功。
- 用代表性普通对局日志和竞技场日志启动打包版，检查主窗口、小窗和退出清理。
- 至少验证 Apple Silicon 安装包；发布前再生成 Intel 安装包或通用包。
- 交付物必须能从本机路径直接安装和启动，不能只留下源码。

## 人工确认项

- 录屏权限仍需人工确认：首次授权后重启安装包，在真实炉石窗口中确认模式、套牌和竞技场候选牌识别正常。
- 空闲基线仍需人工确认：打包应用连续空闲监听 5 分钟，在活动监视器记录 CPU 与内存，并附到本次发布证据。
