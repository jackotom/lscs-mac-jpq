# 实现与数据说明

## 日志读取

应用优先读取 `/Applications/Hearthstone/Logs` 下的最新会话目录，也支持在软件里手动选择日志目录或日志文件。

第一次使用前点“修复日志”，然后完全退出并重新打开炉石。应用会检查并补全 Power、Zone、Decks、Arena 日志配置，修改前保留备份。炉石重开并创建新日志目录后，应用会自动跟随。

构筑模式优先读取炉石记录的已选套牌，无法直接确认时再根据本局抽牌和出牌匹配本机收藏套牌。竞技场会自动累计已选牌；地下竞技场重选后的精确 30 张由同一会话的牌库日志确认。

如果日志只能确认部分竞技场牌，悬浮窗会显示“已确认 N/30”和待识别数量，不使用占位卡冒充完整牌库。

## 卡牌资料

卡牌数据库首次使用时从[官方卡牌浏览器](https://hs.blizzard.cn/cards/)导入传统对战卡牌，并补齐 HearthstoneJSON 的衍生牌。资料保存在本机，之后优先读取本地快照。

牌库、对手出牌和竞技场候选牌会使用本地资料显示名称、法力值、卡牌文字、缩略图和关联牌。图片和文字随数据库缓存，不会每次打开都重新抓取单张卡牌。

## 竞技场统计

竞技场评分使用版本化本地缓存，保留 HearthArena 专家评分和 Firestone 公开统计。低于 2000 个样本会明确标注“样本偏少”；数据缺失时显示“暂无”，不会拿其它指标代替。

## 本机数据

已完成对局按设置保留最近 30、90 或 180 天。只有日志能确认本地玩家结果时才记录，内容不会上传。新记录附带日志可确认的双方职业、先后手、时长、回合和完整套牌版本；历史页可筛选并汇总，旧记录缺失的信息显示未知。

## 留牌与发现辅助

本机从 Power.log 的己方选择、换牌及阶段事件显示起手或发现候选；换牌完成后将实际留牌记录写入对局历史及竞技场档案。选项结束、新对局和暂停时清除辅助，异步统计不会覆盖另一局的选项。

构筑统计使用 Firestone 的准确套牌代码、标准/狂野模式、传说分段和近 7 天口径；当前未细分对手或先后手。竞技场须由日志明确普通/地下模式及职业，使用当前补丁的同职业统计。缺失、过期和身份不匹配时显示暂无，不套用其它套牌。

起手后胜率按换牌后在手样本计算，保留率使用独立的换牌前样本数。构筑发现展示发现该牌后整局获胜比例；竞技场无独立发现统计，仅展示明确标注的抽到后胜率参考。样本不足 200 时标注小样本；保留率提示另外要求换牌前样本至少 200。统计相关性不代表本次选择的因果收益。

在线读取仅发送查询所需的套牌代码、模式和职业，不上传本机对局历史。MAS 运行入口不启用新增在线统计服务。

## 截图复现

README 图片来自当前源码构建出的桌面应用和隔离演示数据。生成命令会先完成构建，再启动四个独立场景：

```bash
npm run screenshots:readme
```

日志、检查记录和用户数据只写入系统临时目录，并在结束后清理。四个场景全部通过后才会整套替换 `docs/screenshots/`。
